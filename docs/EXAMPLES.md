# Usage examples

These prompts are starting points. Replace the target with a URL, local file, repository, screenshot, or Figma reference that Codex can access.

## Restyle an existing website

> Use Design Reference Library to restyle this website in an Apple-inspired direction. Preserve the content, functionality, and product identity. Create a project DESIGN.md and verify desktop and mobile layouts.

Expected result:

- The existing product is inspected before visual decisions are made.
- Only the Apple reference and synthesis guide are loaded.
- The implementation uses general design principles rather than proprietary assets.
- The completed interface is tested at representative breakpoints.

## Discover a reference from a mood

> Use Design Reference Library to make this developer tool feel focused, precise, dark-first, and keyboard-friendly. Recommend up to three references, choose the strongest fit, then implement it.

This is useful when you know the desired feeling but not the brand reference.

## Blend two design languages

> Blend Stripe and Linear for this SaaS product. Use Stripe's editorial pacing and marketing hierarchy for the landing page, and Linear's restraint and density for the application screens.

A strong blend assigns each reference a role. Avoid averaging every token into an indistinct hybrid.

## Create a DESIGN.md without implementation

> Use Design Reference Library to synthesize a project DESIGN.md from the Figma reference. Do not modify the application yet.

This separates art direction from implementation and creates an approval checkpoint.

## Restyle one component family

> Use the Notion reference to redesign this editor's navigation, document chrome, and empty states. Do not alter the rest of the product.

The plugin can be scoped to a component family when a full redesign would be excessive.

## Review an existing restyle

> Review this Apple-inspired implementation using Design Reference Library. Identify deviations in hierarchy, color, spacing, motion, accessibility, and responsive behavior. Do not edit files.

Use review language when you want analysis rather than changes.

## Generate variants

> Create two DESIGN.md variants for this product: one using Linear and one using Stripe. Keep the information architecture identical and explain the trade-offs.

Variants should differ in art direction while preserving the same product requirements.
